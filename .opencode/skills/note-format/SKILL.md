# Форматирование конспектов лекций

Задача — превратить сырой текст (расшифровку встречи, тезисы, черновик конспекта) в наглядный markdown для сайта. Рендер: react-markdown + remark-gfm; HTML в конспектах не отображается. Стиль — как в «Теории личности в психологии/01 Лекция 1.md».

## Порядок работы

1. Прочитай исходный файл полностью.
2. Возьми за скелет шаблон `references/template.md` (путь относительно каталога этого скилла).
3. Переверстай конспект по правилам ниже, сохраняя все факты и авторские формулировки. Ничего не выдумывай; если данных не хватает (например, дата «неизвестна») — так и пиши с пометкой «уточнить».
4. Если у файла нет числового префикса (`01 `) — предложи переименовать: префикс задаёт порядок лекций и не отображается.
5. Проверь разметку скриптом:

   ```sh
   node .opencode/skills/note-format/scripts/check.mjs "<путь к файлу .md>"
   ```

   Скрипт парсит файл тем же стеком, что и сайт, и ругается на «сломанные» таблицы и чек-листы. Предупреждения = ошибка вёрстки, исправь разметку.
6. Не делай commit/push без просьбы пользователя.

## Правила вёрстки

### Каркас файла

- **Frontmatter** (необязателен, в начале файла): `title` — человекочитаемое название для сайдбара, `order` — порядок сортировки. Файл `01 Лекция 1.md` с `title: Установочная встреча` отображается как «Установочная встреча».
- **`# Заголовок`** — ровно один, название лекции/встречи.
- Сразу под ним — **блок метаданных** списком: `- **Спикер:** …`, `- **Дата:** …`, `- **Предмет обсуждения:** …`.
- Разделы — `##`, подразделы — `###`; глубже не уходить.
- В конце — раздел цитат: «Ключевая реплика», «Цитата лектора» и т.п.

### Контент

- **Таблицы вместо перечислений через скобки.** Всё, что похоже на «объект + свойства» (книги и авторы, школы и представители, этапы и смыслы, сравнения), оформляй таблицей `| a | b |`.
- **Важные предупреждения** — блокцитой с жирным лидом: `> **Важно:** экзамен только по обязательному материалу.`
- **Цитаты людей** — блокцитой, подпись отдельной строкой внутри цитаты: `> — И. О. Фамилия`.
- **Чек-листы** встреч/дел — задачами GFM: `- [ ] 19 ноября` (рендерятся чекбоксами).
- **Жирный лид в пунктах списка:** `- **Термин.** Пояснение…` — чтобы суть читалась при беглом просмотре.
- **Последовательности** — стрелками: `индивид → личность → индивидуальность`.
- **Перечень в одну строку** внутри пункта — разделителем `·` (модули курса, темы).
- **Термины-ярлыки** — инлайн-кодом: `` `нозос` ``.
- Курсив — смысловые выделения, жирный — лиды и акценты; без фанатизма.
- Даты: «12 октября 2026 г.»; диапазоны — через тире: «20–40 минут».

### Чего не делать

- Не использовать HTML-теги — они не рендерятся на сайте.
- Не оставлять строки с `|` вне таблицы или `[ ]` вне чек-листа — распарсится как простой текст.
- Не терять содержание: каждый факт исходника должен остаться в вёрстке.
- Не добавлять содержимое от себя (доки, факты, выводы), которых нет в источнике.
