# Конспектирование книг (`books/`)

Задача — прочитать книгу (PDF/EPUB) и написать сжатый, но полный конспект-пересказ:
чтобы по нему можно было «вытащить максимум» из книги без чтения оригинала.

## Структура папки

Каждая книга — в своей папке внутри `books/`, без «россыпи» файлов рядом:

```
books/
  <короткое-имя-книги>/
    Оригинал.pdf        # исходник — имя файла не меняем
    конспект.md         # конспект-пересказ
    settings.json       # карточка книги
```

- **Имя папки** — короткое и говорящее: автор(ы) + краткое название; кириллица допустима,
  пробелы заменяй на дефисы: `болотова-молчанова-психология-развития`.
- **`settings.json`** — карточка книги, четыре обязательных поля, без лишних:

```json
{
  "author": "А. К. Болотова, О. Н. Молчанова",
  "title": "Психология развития и возрастная психология",
  "subject": "Психология развития и возрастная психология",
  "type": "LEARNING_BOOK"
}
```

  - `author` — авторы с титульного листа PDF; определяй сам по исходнику;
  - `title` — точное название книги; определяй сам по исходнику;
  - `subject` — предмет/дисциплина, к которой книга относится; спроси у пользователя;
  - `type` — тип книги; спроси у пользователя, значения:
    `LEARNING_BOOK` (учебник), `MONOGRAPHY` (монография), `GESTALT` (гештальт),
    `OTHER` (другое).

## Порядок работы

1. Прочитай книгу целиком (большой PDF — частями). Не пропускай глав: конспект должен
   покрывать всю книгу. Субагенты обычно не нужны: прочитанный текст книги есть только
   в контексте того, кто его читал, — субагенту пришлось бы перечитывать PDF с нуля.
2. Составь план конспекта по оглавлению: введение → части/главы → итоговые тезисы.
3. Заполни `settings.json`: `author` и `title` определи по PDF (титульный лист),
   `subject` и `type` спроси у пользователя.
4. Пиши `конспект.md` в папке книги. Файл получается большим — пиши частями: сначала
   `write` шапку и начало, дальше дополняй `edit`ом, цепляясь за последние строки
   предыдущей вставки.
5. Ничего не досочиняй: каждый факт конспекта — из книги. Если каких-то данных не
   хватает — не заполняй пробел домыслами.

## Вёрстка конспекта

Строго по правилам скилла **note-format** (`.opencode/skills/note-format/SKILL.md`):
таблицы вместо перечислений, жирные лиды в пунктах, стрелки-последовательности,
термины инлайн-кодом, ровно один `#`, без HTML. Отличия от лекционного конспекта:

- файл лежит в `books/`, а не в `content/` — frontmatter `title`/`order` не нужен;
- внутри главы разрешён четвёртый уровень `####` — для тематических блоков
  (подходов, методов, возрастных периодов) в больших главах;
- если у главы/периода в источнике есть сквозной итоговый рубрикатор — повторяй его
  итоговым пунктом (в учебнике по психологии развития это «новообразования»);
- в конце — раздел «Главные идеи»: 5–10 тезисов всей книги.

### Разметка по разделам файла

**Шапка файла** — один `#` и блок метаданных:

- `# Название книги — конспект` — ровно один заголовок первого уровня;
- сразу под ним список метаданных с жирными лидами: `- **Источник:**` авторы,
  точное название, издательство, год, число страниц; `- **Структура:**` сколько
  частей и глав, что охватывает; `- **Назначение конспекта:**` сжатый пересказ
  для повторения курса.

**Вводный раздел** (по желанию): `## Общий замысел книги` или похожий — 3–5
пунктов о том, о чём книга, как построена и на кого рассчитана.

**Части и главы** — иерархия заголовков:

- `## Часть I. Название части` — по частям книги (если книга на части делится);
- `### Глава N. Название главы` — по главам, названия как в источнике;
- `#### Тематический блок` — крупные смысловые куски внутри больших глав.

**Содержимое глав** — те же элементы, что в note-format:

- основной элемент — маркированный список с жирным лидом:
  `- **Термин или тезис.** Пояснение…`;
- сравнения, классификации, периодизации, «объект + свойства» — таблицей `| a | b |`
  (позиции подходов по вопросам, стадии и возрасты, стратегии и их плюсы/минусы);
- последовательности и цепочки — стрелками: `инстинкт → дрессура → интеллект`,
  `отрицание → гнев → торг → депрессия → принятие`;
- термины-ярлыки — инлайн-кодом: `` `сензитивный период` ``, `` `витаукт` ``;
- важные оговорки и цитаты людей — блокцитой с подписью `> — И. О. Фамилия`;
- перечень в одну строку внутри пункта — разделителем `·`.

**Итоговый рубрикатор**: если в источнике у каждого периода/главы есть сквозной
итог, завершай раздел последним пунктом `- **Новообразования:** …` (или как он
называется у авторов).

**Финал**: `## Главные идеи книги` — 5–10 тезисов всей книги, каждый пункт
начинается с жирного лида.

## Проверка

```sh
node .opencode/skills/note-format/scripts/check.mjs "books/<папка>/конспект.md"
```

Предупреждения = ошибка вёрстки, исправь разметку. `npm run build` не нужен: `books/`
не сканируется сайтом, это не `content/`.

## Если книга уже законспектирована «россыпью»

Файлы книги лежат прямо в `books/` рядом — приведи к структуре: создай папку,
перенеси исходник и конспект (конспект переименуй в `конспект.md`), добавь
`settings.json`. Пути меняются — предупреди об этом пользователя.

Не делай commit/push без просьбы пользователя.
