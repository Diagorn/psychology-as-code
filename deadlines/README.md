# Дедлайны

В этой папке лежат данные для страницы «Дедлайны» сайта. Каждый **JSON-файл — один
учебный предмет**: материалы с прогрессом, дедлайны по ним и события (экзамены,
зачёты и т. п.). Страница читает все `*.json` из папки автоматически — регистрировать
файл нигде не нужно: положили файл, и предмет появился.

## Как добавить новый предмет

1. Создайте в этой папке файл с именем на латинице, например `gestalt-therapy.json`.
2. Заполните его по структуре ниже.
3. Готово: dev-сервер подхватит файл сразу (HMR), на сайте он появится после сборки.

Даты подставляются сами: прогресс материалов считается от сегодняшнего дня между
`startDate` и `endDate`, а у дедлайнов показывается обратный отсчёт («через 4 дня»,
«завтра», «сегодня», «5 дней назад»).

## Структура файла

```jsonc
{
  "id": "developmental-psychology",   // строка, необязательно: идентификатор предмета
  "name": "Психология развития",      // строка: название предмета на странице
  "materials":  [ /* что нужно пройти */ ],
  "deadlines":  [ /* контрольные точки с требованиями */ ],
  "events":     [ /* экзамены, зачёты и прочее */ ]
}
```

Поддерживается и форма с обёрткой — `{ "subjects": [ { … }, { … } ] }`, где в одном
файле лежит несколько предметов. Битый JSON пропускается целиком, страница не падает.

### materials[] — что нужно пройти

| Поле        | Тип     | Обязательно | Описание                                            |
| ----------- | ------- | ----------- | --------------------------------------------------- |
| `id`        | строка  | да          | Уникальный в файле идентификатор, на него ссылаются требования |
| `name`      | строка  | да          | Название: «Видеолекции», «Чтение учебника»          |
| `unit`      | строка  | нет         | Единица измерения: «модуль», «глава» (по умолчанию «ед.») |
| `total`     | число   | да          | Сколько всего нужно пройти за семестр (> 0)         |
| `startDate` | дата    | да          | Когда начинается прохождение, формат `YYYY-MM-DD`   |
| `endDate`   | дата    | да          | Крайний срок прохождения, формат `YYYY-MM-DD`       |

### deadlines[] — контрольные точки

| Поле           | Тип     | Обязательно | Описание                                        |
| -------------- | ------- | ----------- | ----------------------------------------------- |
| `id`           | строка  | нет         | Идентификатор (иначе сгенерируется `deadline-N`) |
| `date`         | дата    | да          | Дата дедлайна, `YYYY-MM-DD`                     |
| `requirements` | массив  | нет         | Что должно быть пройдено к этой дате            |

Каждый элемент `requirements`:

| Поле         | Тип    | Обязательно | Описание                                          |
| ------------ | ------ | ----------- | ------------------------------------------------- |
| `materialId` | строка | да          | `id` материала из `materials` (чужой id игнорируется) |
| `target`     | число  | да          | Сколько единиц материала должно быть пройдено (> 0) |

### events[] — события

| Поле   | Тип    | Обязательно | Описание                                          |
| ------ | ------ | ----------- | ------------------------------------------------- |
| `id`   | строка | нет         | Идентификатор (иначе сгенерируется `event-N`)     |
| `name` | строка | да          | Название события                                  |
| `date` | дата   | да          | Дата события, `YYYY-MM-DD`                        |
| `type` | строка | нет         | Тип события, влияет на метку и иконку             |

Известные значения `type`: `exam` (Экзамен), `credit` (Зачёт), `test` (Контрольная),
`consultation` (Консультация), `colloquium` (Коллоквиум), `practice` (Практика).
Неизвестное значение не сломает страницу — событие просто показывается без метки.

## Как страница это показывает

- Предметы сортируются по конечной дате: те, что заканчиваются раньше, — сверху.
- Завершённые предметы (у которых **все** даты в прошлом) не отображаются.
- Прогресс материала — план по времени: сколько прошло от `startDate` к `endDate`
  на сегодня. Рядом — «≈ N из total единиц» и сколько времени осталось.
- На шкале материала флажком отмечена цель ближайшего несостоявшегося дедлайна.
- У дедлайна — бейдж-отсчёт: красный, если осталось 3 дня и меньше (а также
  «сегодня»/«завтра»), янтарный — за 4–7 дней, фиолетовый — дальше. Прошедшие
  дедлайны приглушаются.
- Возле каждого требования — метка «план успевает» или «план отстаёт: ≈X из Y»:
  сравнивается, сколько материала будет пройдено по плану к дате дедлайна.

## Единицы измерения и склонения

Для известных единиц число и слово согласуются автоматически: «1 модуль, 2 модуля,
5 модулей». Известные слова: `модуль`, `глава`, `лекция`, `видеолекция`, `тема`,
`раздел`, `параграф`, `статья`, `книга`, `тест`, `кейс`, `задание`, `работа`,
`проект`, `практикум`, `семинар`, `эссе`. Неизвестная единица выводится как есть
(без склонения) — если хотите правильные формы, выбирайте слово из списка или
добавьте его в `UNIT_FORMS` в `src/lib/deadlines.ts`.

## Пример

Файл `deadline-example.json`:

```json
{
  "id": "developmental-psychology",
  "name": "Психология развития",
  "materials": [
    {
      "id": "lectures",
      "name": "Видеолекции",
      "unit": "модуль",
      "total": 50,
      "startDate": "2026-10-01",
      "endDate": "2027-02-01"
    },
    {
      "id": "reading",
      "name": "Чтение учебника",
      "unit": "глава",
      "total": 12,
      "startDate": "2026-10-01",
      "endDate": "2027-02-01"
    }
  ],
  "deadlines": [
    {
      "id": "deadline-1",
      "date": "2026-10-28",
      "requirements": [
        { "materialId": "lectures", "target": 2 },
        { "materialId": "reading", "target": 1 }
      ]
    }
  ],
  "events": [
    {
      "id": "exam",
      "name": "Экзамен по психологии развития",
      "date": "2027-02-05",
      "type": "exam"
    }
  ]
}
```
